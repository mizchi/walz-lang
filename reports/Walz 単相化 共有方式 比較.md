# Share generic code without weakening Walz

**Walz can share code across different generic instantiations while preserving static types.** The smallest useful next step is to measure equivalent lowered bodies, factor substantial type-independent work into helpers, and try exact function merging before designing a dictionary runtime. Same-declaration, same-type-argument reuse already exists; high specialization counts alone do not establish avoidable duplication. Other languages use several combinations of specialization, shared representations and runtime evidence, with different costs. For Walz, the safe boundary is complete source checking followed by implementation sharing: nominal identity, opacity, ownership and effects remain intact. The other self-hosting findings call for explicit WAT boundaries, consistent control-flow typing and better origin traces, rather than a broad expansion of language features.

## Existing caches already remove repeated identical requests

The bootstrap keys instances by declaration identity and normalized type arguments, then caches signatures, return types and layouts. Rust uses a template/argument cache and a work queue. These mechanisms reuse an existing concrete instance; they do not establish that different instances require different machine code. ([Bootstrap lookup](../walz/frontend/generics.walz), [Rust expansion](../src/generics.rs))

One retained compiler profile contains **119,985 requests, 118,783 cache hits and 1,202 distinct instances**: 749 functions, 398 heap types and 55 aliases. The function total includes nongeneric declarations. It also records 248,612 syntax nodes. Neither number identifies redundant generic bodies. The fixed-point proof produces matching 485,920-byte compiler stages and matching 487,168-byte portable modules, but those totals are not a breakdown of generic overhead. ([Profile capture](../target/selfhost-validation/tuning-clean-final/compiler.json), [Stage capture](../target/selfhost-validation/stages-verified/report.json))

The missing measurement is a per-template inventory: generic versus ordinary functions, concrete arguments, lowered signatures, dependency edges, instruction counts, emitted code bytes and equivalent-body groups. Type-section growth must be reported separately. Merging functions does not automatically remove their specialized GC types, aliases or metadata. A symbolic IR template could also reduce substitution allocations while still emitting distinct concrete functions; this addresses compiler work without changing runtime representation.

## Other languages choose different sharing boundaries

| Implementation | How generic code is represented | Lesson for Walz |
| --- | --- | --- |
| Rust | Concrete instances are collected and monomorphized; reachability includes function references and generated glue. | Preserve demand-driven collection, then distinguish instance caching from sharing different implementations. ([Compiler guide](https://rustc-dev-guide.rust-lang.org/backend/monomorph.html), [Collector](https://doc.rust-lang.org/stable/nightly-rustc/rustc_monomorphize/collector/index.html)) |
| C++ and native linking | Identical-code folding can merge equivalent compiled sections using their contents and relocation relationships. | Late folding reduces shipped code, not the template/IR work already performed. Address-sensitive functions require care. ([LLD ICF algorithm](https://github.com/llvm/llvm-project/blob/main/lld/ELF/ICF.cpp)) |
| Go | Shape-specific bodies take dictionaries carrying concrete type and operation information. Current shaping remains conservative. | Share only compatible operation/representation groups; equal size is insufficient. ([Go 1.18 implementation design](https://go.googlesource.com/proposal/+/refs/heads/master/design/generics-implementation-dictionaries-go1.18.md), [Current Shapify](https://go.dev/src/cmd/compile/internal/noder/reader.go#L959)) |
| Swift | Shared generic code uses metadata and witness operations; visible definitions and concrete types permit specialization. | Shared cold algorithms and specialized hot paths can coexist, at the cost of metadata and runtime abstraction. ([Generics implementation book](https://download.swift.org/docs/assets/generics.pdf), [Optimization guide](https://github.com/swiftlang/swift/blob/main/docs/OptimizationTips.rst#generics)) |
| .NET | Compatible reference instantiations share canonical code while dictionaries retain concrete information; value-type instantiations generally specialize. | Separate source type identity from implementation identity, and count metadata as part of AOT size. ([Shared generics design](https://github.com/dotnet/runtime/blob/main/docs/design/coreclr/botr/shared-generics.md), [NativeAOT architecture](https://github.com/dotnet/runtime/blob/main/docs/design/coreclr/botr/ilc-architecture.md#compiling-generics)) |
| Java | Erasure avoids a new generic class per parameterization; casts/bridges restore source typing, and primitive values use wrappers when passed through reference-oriented generics. | Global erasure is a poor default for unboxed numeric/SIMD workloads. ([JLS erasure](https://docs.oracle.com/javase/specs/jls/se26/html/jls-4.html#jls-4.6), [Boxing](https://docs.oracle.com/javase/specs/jls/se26/html/jls-5.html#jls-5.1.7)) |

These descriptions are implementation choices, not interchangeable language requirements. Go's historical 1.18 design and current compiler source must be distinguished: current `Shapify` principally uses underlying types, with a restricted pointer canonicalization. It explicitly leaves broader sharing to future type-usage analysis. Likewise, Java SE 26 is the specification edition consulted, not a claim about the latest installed JDK.

Rust's former unused-parameter polymorphization was removed in December 2024. A separate 2026 experimental goal investigates monomorphic data with shared polymorphic code; it is not evidence that stable Rust has adopted that baseline. Walz can study the technique without claiming to reproduce a current Rust feature. ([Removal decision](https://github.com/rust-lang/compiler-team/issues/810), [Experimental goal](https://github.com/rust-lang/goals/blob/main/src/2026/polymorphization.md))

A smaller precedent is immediately useful: Rust's generic `fs::read<P: AsRef<Path>>` converts the argument and delegates its substantial work to a nongeneric inner function. This retains a convenient typed entry while compiling the algorithm once. Equivalent factoring in Walz needs no new generics syntax or universal value representation. ([Standard-library source](https://doc.rust-lang.org/src/std/fs.rs.html))

## Share checked implementations before adding dictionaries

The recommended first experiment uses the inventory above and the existing pinned Binaryen workflow. Upstream Binaryen has `DuplicateFunctionElimination` for equivalent lowered functions and `MergeSimilarFunctions` for bodies differing in selected constants or callees, retaining parameterized helpers and thunks when profitable. These mechanisms must be tested separately. Their presence on upstream `main` does not verify which options exist or run by default in Walz's pinned version 133; normal Walz builds currently do not invoke this optional postprocessor. Use a fresh versioned capture before drawing conclusions. ([Exact elimination](https://raw.githubusercontent.com/WebAssembly/binaryen/main/src/passes/DuplicateFunctionElimination.cpp), [Similar-function merging](https://raw.githubusercontent.com/WebAssembly/binaryen/main/src/passes/MergeSimilarFunctions.cpp), [Walz workflow](../docs/wasm-opt.md))

For a future internal pass, start with **private, non-address-taken direct-call functions with identical physical signatures and bodies**. Normalize local/label names, retain every instruction immediate and concrete heap/callee identity, use a hash for candidate selection, then compare structurally. Equivalent mutually recursive groups need call-graph refinement rather than naive byte comparison. Remap resolved indices consistently and independently validate the rewritten module. Preserve distinct wrappers when exported or reference identity is observable: the Wasm JS API caches exported-function objects by function address. ([JS object caches](https://webassembly.github.io/spec/js-api/index.html#webassembly-js-object-caches))

The distinction between source and implementation identity is essential. Every requested source instantiation must still pass its constraints, opacity, ownership, effect and ABI checks and retain its original diagnostic origin. Only the implementation can be shared. Do not replace source types with a common name or skip a rejected instantiation because a compatible implementation already exists.

The following are semantic sketches, not proposed syntax:

```text
answer<T>() -> i32 = 42             // potentially one implementation
add<T: Add>(a: T, b: T) -> T = a+b  // operation and physical types matter
length<T>(xs: List<T>) -> i32       // depends on the actual GC representation
```

Even `length<T>` cannot share merely because its result is always i32. A typed `struct.get` names a particular heap type and field representation. Similarly, i32/f32 both occupy 32 bits but require different operations; signedness, casts, nullable references and mutable storage can change behavior. Sharing an algorithm does not authorize merging distinct GC type declarations or foreign opaque layouts. ([Wasm struct validation](https://webassembly.github.io/spec/core/valid/instructions.html#valid-struct-get))

After exact merging and helper factoring, consider **codegen-irrelevant type-argument analysis**. A parameter is irrelevant only when it affects neither physical signatures/locals, GC operations, selected operators, macro type queries, ABI operations nor transitive callees. Recursive dependencies require a fixed point. Unknown macro behavior should conservatively retain the parameter. This analysis is harder than checking whether a type variable is textually absent, so it belongs after the simpler experiments. Late merging mainly saves final bytes; safe early sharing can save expansion work and peak IR storage, while retaining complete source validation.

Shape/dictionary sharing is a later option for large remaining duplicates. A typed wrapper could pass resolved operation evidence to a common algorithm, preserving distinct source types. The price includes dictionaries, wrappers, indirect calls, casts or boxing, and potentially lost inlining. The bounded backend also lacks the full function-reference/callable/import support such dictionaries would need. Blanket erasure into `anyref` would undermine the numeric/SIMD representation goal; it should not become the default merely to reduce function counts. Keep direct specialization for hot primitive operations unless matched measurements favor another choice.

## Make WAT boundaries and control typing explicit

The grammar issue is concrete: WAT permits a label after `if`, while the bootstrap recognizes a bare name followed by `then` as a local-condition shorthand. A local lookup must not reinterpret a valid native WAT label. Require `(local.get $ready)` in an ambiguous native position, or select a separately marked extension such as a future `@if`; decide one spelling and apply it consistently in Rust and bootstrap. Ordinary WAT remains authoritative, rather than depending on which names happen to exist in scope. ([WAT labels](https://webassembly.github.io/spec/core/text/instructions.html#labels), [Current regression cases](../runtime/selfhost-front/control.mjs))

For typing, define a small common contract: synthesize types for locally determined forms, check other expressions against an expected type, assign unit context to nonfinal statements, require i32 conditions and propagate declared result vectors to control tails. Track a label environment and reachable/unreachable state. `return`, unconditional branches and `unreachable` follow Wasm's stack-polymorphic rules; they are not ordinary unit-valued expressions. Explicitly introduced incompatible operands must still fail even in unreachable code. This resolves the observed context bugs without introducing unrestricted inference or default numeric widths. ([Wasm validation](https://webassembly.github.io/spec/core/valid/instructions.html), [Current fixes and limits](../docs/selfhost-stages.md))

Use one shared conformance corpus for native WAT, extended source, ambiguous spellings and negative unreachable/skipped-branch cases. Numeric locals, labelled if and multiple statements in branches currently sit outside the Rust typed `@use` comparison gate; that separation documents a gap, not a permanent semantic policy. Keep current single-result limitations explicit until vector-based control validation and emission support more.

## Preserve origins and measure each kind of saving

The compact project error currently carries file/code/start/end, and code 118 combines invalid and unsupported type/declaration cases. Improve diagnostics with an optional bounded origin chain: generic request/declaration, macro invocation/definition, lowered node and validation phase. Distinguish unsupported source features, invalid programs and internal lowering invariant failures. Attach stable origin IDs and share trace tails rather than copying prose through every node. A shared implementation must retain caller origins on its incoming edges; one body's origin cannot stand for every source instantiation. ([Current error API](../docs/selfhost-frontend.md), [Host messages](../runtime/selfhost.mjs))

Keep the small Wasm compiler responsible for structured facts, while the host formats explanatory text and source names. Existing portable clients need either an optional versioned extension or a separate inspection API. Tests should cover nested imported macros/generics, UTF-8 ranges, expected/actual types, source rather than generated names, trace limits and ABI retirement on success and failure.

For sharing, positive tests should cover repeated identical requests, genuinely unused parameters, transitive dependencies, deterministic exact merges and recursion. Exclusions must cover numeric widths/signedness, floating-point edge cases, v128 lanes, casts/nullability, opaque layouts, constraints, type-querying macros and ABI/resource operations. Exported functions, tables, element segments and `ref.func` need explicit identity/remapping cases when supported. Preserve evaluation order, traps and reference identity throughout.

Measure raw code-section bytes, type-section bytes, total/compressed size, expansion and validation time, logical node/work counters, actual memory separately, engine compilation/startup and representative execution. Retain frozen inputs, both artifacts and raw samples. The existing **332-case stage gate and 175-case shared Rust gate** remain required; byte-changing optimizations need behavior preservation and deterministic new stage output, not equality to old unoptimized bytes. No new benchmark was run for this report, and no percentage saving is established. ([Stage contract](../docs/selfhost-stages.md), [Parity contract](../docs/selfhost-parity.md), [Tuning protocol](../docs/selfhost-tuning.md))

The practical decision is therefore evidence-driven: use common helpers and exact sharing where the inventory shows substantial repeated work, and reserve dictionaries for duplication those techniques cannot remove. A small language can support this entirely as compiler policy while keeping its source type system precise.
