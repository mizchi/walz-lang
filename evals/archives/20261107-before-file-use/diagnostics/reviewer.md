# 親による診断評価の監査

読解役が全ケースについて、原因・修正案を実際のコードと診断に照合できているか確認する。
corpus、suite.json の期待位置/意図、正常対照、非公開テストを使ってよい。これらを読解役/修正役へ渡さない。
診断に書かれていない期待型や修正方法を、コードから推測しただけで満点にしていないか確認する。
位置がずれる、owner名がない、二次エラーしか示さない等は、拒否できても品質の問題として残す。

監査してから記録する:
{{REVIEW_COMMAND}}
誤答なら --correct を --incorrect にする。理由を具体的に記録する。

{{VERIFY_COMMAND}}
{{SCORE_COMMAND}}

修正成功だけで品質を合格にしない。全ケースの全軸3以上、監査成功、正常対照と修正の振る舞いテスト成功、元コードの正しい拒否と位置をすべて要する。
