# `%` 構文の初見評価（suite v6）

チートシートと在庫台帳サンプルを、履歴を持たない読解役・変更役へ別々に配布した。読解役には依存実装を渡さず、変更役には完成した行数カウント版を渡していない。親が説明を凍結資料へ照合し、サンプルと変更候補を実行検証した。

round 1 では、関数ヘッダーと本体の区切り、括弧の配置で確認の負担が残った。関数の引数・結果・effect を行ごとに配置し、閉じ括弧を式の末尾へ付け、補助関数を `$process-counted-line` に改名した。I/O に成功した配送行数を数えることもコメントで明示した。

round 2 は全5軸が基準の3以上になり、標準 WAT と `%` 拡張、結果宣言と Result 値型、shared/pure/opaque の限界について誤読がなかった。

[round 1](round-1/summary.json)・[round 2](round-2/summary.json) に採点時点の結果、各ディレクトリに配布物・回答・監査・実行証拠を保存した。[比較](comparison.json) は保存済み結果の比較であり、現在の実装での再検証結果ではない。ビルド用の `work/` は保存していない。

これは同じモデルによる少数の主観評価であり、人間の作業時間や統計的な改善効果を示さない。後続の標準型 import と複数束縛は [suite v7](../20261106-standard-bindings-v7/REPORT.md) で質問を追加して評価したため、v6 との点差は比較しない。
