## 改善した診断

- **case-01 数値型（repair 2→4）**: オペランド側の i64 要求に加え、周辺が i32 を期待していることを表示。意図が i32 演算なら i32.add と全オペランド・数値定数の型をそろえる条件付き help を追加した。実在し、型と引数数が合う演算だけを候補にし、暗黙の変換はしない。
- **case-06 alias 循環（location 2→4、repair 2→3）**: $Input → $Output → $Input の順序付き経路と、各参照の位置を表示。循環を閉じる参照を主位置にし、意図する具体型または循環外の型へ1辺を置き換える方針を表示した。i32 という仕様上の意図は推測しない。
- **case-08 include 先の未定義変数（expectation 2→4、repair 2→4）**: 近い綴りがない場合も、現在のスコープで使える束縛の名前・型・宣言位置を最大4件表示。置換先と断定せず、既存の束縛を使う意図なら参照名を確認する help を追加した。

include をまたぐ alias の関連位置も追加の回帰テストで確認した。
ケース・意図・基準・正常対照・非公開テストは変更していない。

## 残る改善候補

全軸が目標を満たしたため、今回の改善はここで完了とする。読解役から残った候補は次のとおり。

1. match の不足 case に、型の宣言位置・payload の個数と型・束縛構文を添える。
2. 引数不足に、欠けた parameter の名前と型を添える。渡す値は推測しない。
3. 所有値を再消費できない規則と、必要な消費を保った対処方針を短く明示する。
4. 閉じ括弧不足に、開き括弧の位置と EOF の位置を併記する。
5. opaque 診断に拒否した操作名を添える。公開 API の候補は型から確実に絞れる場合だけ示す。
6. effect の許可を選ぶ場合の注釈例を条件付きで示す。
