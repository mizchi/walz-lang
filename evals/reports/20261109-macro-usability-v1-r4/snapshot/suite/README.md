# マクロの実用性を検査する

JSONの検証・分類集計を「直接記述」「通常関数」「推論情報を使うマクロ」の3通りで実装し、同じ入力と独立したBigInt oracleで比較する。実装者による試用であり、初見の人間による可読性評価ではない。[課題](contract.md)と[ルーブリック](rubric.md)を固定してから実行する。

```sh
just eval-user-macros trial-01
```

Node.js 24以降、Rust 1.99、Wasm GC対応Wasmtime、インストール済みのpnpm依存を使う。結果は`evals/runs/trial-01/`へ保存する。既存IDの上書きは拒否する。コンパイラやランタイムを修正したら、新しいIDで実行する。

- `snapshot/`と`inputs.json`: 課題・資料・コード・入力生成器を固定したもの。
- `manifest.json`: CLIのハッシュ、コンパイラとランタイムのソースハッシュ、Node版。
- `commands.json`: 実際のCLI引数・終了コード・出力・経過時間。
- `result.json`: 必須検査、未達の探索課題、記述量、生成サイズ、コンパイル・実行の計測値。
- `work/`: 両backendの生成物とLSPの実応答。

`passed`は必須検査の合否。`unmetTasks`に残る探索課題も実用性の判断に含める。必須検査の成功だけで「実用上の不足がない」とは判定しない。

Core＋JSPI／Componentで、7組の入力×2方針×3実装を照合する。各呼出し後のABIバッファと端点表の空状態、マクロ内の中断・取消しも検査する。任意のGCヒープのリーク不存在は証明しない。

CLIのcheck/buildは順番を均等に入れ替えた7回、実行はウォームアップ後9回を記録する。CLIの計測は起動・読込み込みで、型検査器だけの時間ではない。実行は128行を渡すSDK呼出しとABI変換込み。単一端末の短い測定から普遍的な速度差や人間の作業時間は主張しない。

`app/model.wlt.in`は3実装に共通する集計本体。評価器がparserのパスだけを変えたモジュールとentryを作り、それらも実行前に固定する。`app/parse-*.wlt`と`app/syntax.wlt`で共通化の方式を比較できる。

最初の結果は[20261109の評価](../reports/20261109-macro-usability-v1-r1/REPORT.md)。この回の必須20検査は成功し、束縛の委譲・反復、未完コードの補完、大きい呼出し数の4課題が未達だった。
