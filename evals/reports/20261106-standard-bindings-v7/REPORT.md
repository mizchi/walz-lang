# 標準型 import と複数束縛の初見評価（suite v7）

`wlt:std` の明示 import、Result / Option / Future の `%inst`、左から右に評価する複数束縛の `%let` をチートシートと在庫台帳へ反映し、履歴を持たない読解役・変更役で2回評価した。役ごとの資料を分離し、説明の正しさは親による監査、動作は固定チェックで確認した。

両回とも、標準名は import したスコープで使うこと、型名と `%future.await` 等の固定構文の違い、複数束縛の評価順と明示 move、pair 分解と Wasm 複数戻り値の違いを正しく説明できた。変更役は台帳参照と行数を pair の状態に保持し、I/O 成功後だけ加算した。EOF・入力失敗・出力失敗・取消しの終了処理と、管理ハンドル数・ABI live=0 も実行で確認した。

round 1 では、課題の契約表に旧来の基本型表記が残り、チートシートにも標準ライブラリを include する説明が混在していた。表を明示 import と `%inst` にそろえ、`%include "program.wlt"` は課題の宣言挿入、標準ライブラリの入口は `wlt:std` と説明した。round 2 は新しい配布物を凍結して実施し、この混同を解消できた。点数は変わっていない。

残る確認負担は fold の位置引数と括弧、同じ `i32` を使う成功型とエラー型の識別にある。独立配布のチートシートは標準 API 全体の型・effect 一覧や取消しの具体手順までは含まない。詳細は [標準モジュール](../../../docs/standard.md)・[標準ライブラリ](../../../stdlib/README.md)・[ランタイム](../../../docs/runtime.md) を参照する。

[round 1](round-1/summary.json)・[round 2](round-2/summary.json) に採点時点の結果、各ディレクトリに配布物・回答・監査・実行証拠を保存した。[比較](comparison.json) は保存済み結果の比較であり、現在の実装での再検証結果ではない。ビルド用の `work/` は保存していない。
