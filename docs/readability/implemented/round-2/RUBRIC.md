# コードの可読性を評価する基準

以前の grammar-eval は正確な理解と変更可能性を測った。ここではコードを追う負担を評価する。
コンパイル・実行成功は別の前提条件とし、可読性の加点に使わない。前の20点とも比較しない。
採点は主観を含む。行番号と具体的な箇所を根拠にし、機械計測は行数・深さ・反復箇所の確認にだけ使う。

各軸0〜4。0=構造を判別できない、1=繰り返し資料や別の箇所へ戻る、2=追えるが目立つ負担がある、3=小さな確認だけで追える、4=局所的にほぼ迷わず読める。

| 軸 | 見るもの |
|---|---|
| flow | main の開始、行ごとの処理、成功時の戻り値がコードから順に追えるか |
| types | 必要な型と処理が区別できるか。同じ複合型の反復や裸の型引数を覚える負担 |
| scope | 束縛と利用箇所を対応させられるか。入れ子・名前・閉じ括弧を追う負担 |
| layout | 関数の契約、マクロのヘッダー、case の束縛がまとまり、式の区切りが見えるか |
| changes | 行数カウンタの導入・変更を、型注釈や包み直しの探索に邪魔されず読めるか |

全軸3以上を可読性の目標にする。総点で弱い軸を相殺しない。説明を追加しただけで types/changes を満点にしない。

今回は実装済み構文を評価する。新しい初見の読解役で再評価し、前回の得点は渡さない。未達の軸があれば最大2回、指摘に沿ってサンプルか実装を修正する。得点だけのために基準は変更しない。
