# 標準ライブラリの共通化

bytes/text の検索・最初の区切りでの分割・検査付き十進数解析と、text / JSON object の builder を追加した。
ログ集計・在庫台帳・workflow のタブ検索と整数解析を共通化し、JSON 出力をフィールド単位の API に置き換えた。
言語の構文・型・コンパイラ・JS ランタイムは変更していない。

`buffer.parse-u64` は範囲と上限を引数に取り、アプリ固有の上限（u32 最大値／100万）は呼出し側に残す。
JSON はキー・値をエスケープし、入れ子 object と区切りを管理する。builder の finish は断片への参照を外す。
意味・API・未対応の JSON 値は [標準ライブラリの契約](../../stdlib/README.md) にまとめた。

変更前の b0d3378 と変更後のソース・生成物を別々に capture した。
[生の測定値と全 capture ハッシュ](20261105-comparison.json) に入力、期待値、Wasm、JS とソースの対応を保存している。
ローカルの成果物は `target/stdlib/before` / `target/stdlib/after-final` にあり、再測定コマンドは次のとおり。

```sh
just stdlib-compare target/stdlib/before target/stdlib/after-final 7
```

Node v24.21.0、Apple M5、Core＋JSPI、インメモリの入力・出力で測定した。
各版を3回実行してから、10回の平均を1サンプルとして7回測定し、変更前後の順序を交互にした。
ビルド・instantiate と事後の照合は時間に含めず、各呼出しの出力、入力の終了1回、ABI の未解放数0を照合した。
以下の時間はサンプルの中央値。

| アプリ | 変更前 ms | 変更後 ms | Core Wasm bytes（前 → 後） |
| --- | ---: | ---: | ---: |
| ログ集計 | 1.395 | 1.409 | 10,447 → 13,942 |
| 在庫台帳 | 3.920 | 3.790 | 11,617 → 15,192 |
| workflow | 0.482 | 0.499 | 19,533 → 22,966 |

今回は共通化と境界の契約が目的で、3アプリ共通の高速化は確認していない。短い処理での数％の差だけでは性能改善とは判定しない。
ソースの重複を減らした一方、標準ライブラリの関数が増え、生成サイズは約3.4–3.6KB増えた。
現状の emitter は未使用関数も出力する。未使用関数の除去と一時値の簡約は、別の意味保存検査を伴う最適化として残す。
Component / Chromium の結果・取消し・解放は実行テストで確認し、この表の速度比較には含めない。

回帰検査は `just check`、Rust 200件、言語内テスト41件、Node 43件、Chromium 24件、評価ハーネス11件が成功した。
追加した検査は不正範囲・空入力・u64/s64 の境界、非 ASCII 数字、UTF-8 境界、空の区切り、任意 bytes の検索、2048断片の結合、finish 後の再利用と別名、opaque / effect 違反を含む。
チートシートの include 付き完全モジュールも、ファイルローダー経由でコンパイルしている。
