# 文法資料とサンプルの評価規約

対象は、CHEATSHEET.md と在庫台帳 main.gwat を初めて読んだ人が、型・制御・終了処理を理解し、変更できるか。
同じサンプルを読んだ感想だけでは採点せず、読解回答とコンパイル・実行の結果を残す。
この基準は最初の評価前に固定し、ラウンド間で変更しない。

## 入力と役割

- 読解役：前の会話・評価結果を渡さない。配布したチートシート・サンプル・API契約・設問だけを読む。実装・SPEC は検索しない。
- コード変更役：同じ資料から変更課題を実装する。CLI の check / types / fmt は利用可。既存実装を読んだり変更したりせず、指定ディレクトリの candidate.gwat と自己報告だけを作る。
- 親：配布物をスナップショット化し、読み間違い・欠けた説明を分類する。固定した実行例で候補を検証し、自己採点とは別に最終得点を付ける。

## 固定ルーブリック（各4点、計20点）

各軸は下記4項目の正答／充足を1点ずつ数える。未回答・推測だけの回答・部分的な充足は0点。
感想だけによる加点や、検査失敗を高い総得点で相殺することはしない。

| 軸 | 1点ずつ確認する4項目 |
|---|---|
| G 構文 | 結果宣言と Result 値型の区別、result.let の裸の型引数の役割、unit の束縛、ローカル束縛のスコープ |
| T 型の流れ | 入力の型、fold の状態型、fold 全体の結果型、処理関数の結果型 |
| C 制御と終了 | EOF、I/O エラーの伝播、業務エラーとの区別、GC 参照と所有端点・取消しの区別 |
| W 変更の実行 | 型検査・Wasm 検証、成功値と JSON の一致、エラー時の解放、要求した pair 状態と初期化回数 |
| D 資料の十分性 | 未定義の構文記号がない、APIを推測しない、パスとコマンドを再現できる、追加の資料探索なしに解ける |

重大条件：G の結果宣言／値型と裸の型引数、C の全項目、W の全項目を満たすこと。
合格は重大条件を全て満たし18/20以上。原資料不足と、説明されているのに読み落とした問題は分けて記録する。

## 課題

1. **読解**：元の在庫台帳 main の型の流れ、EOF・業務エラー・I/O エラー、GC と端点の寿命を説明する。
2. **変更**：台帳の参照と配送行数を pair で持ち、成功時に配送された行数を返す。空行・コメントも数え、EOF は数えない。元の出力、業務エラーの継続、I/O エラーの伝播を維持する。
3. **保留課題**：最終ラウンドで別の読解例を追加し、語句の暗記だけになっていないことを確認する。

コード変更役には模範解答や実行用の期待値を渡さない。試験データは親の verifier に固定する。
変更したコードの実行は子プロセスで行い、タイムアウトを設ける。

## 改善と停止

毎回、新しいエージェントを用い、前の得点や指摘は渡さない。同一モデルの評価なので人間の利用者全体への一般化はしない。
指摘→原因→修正対象→機械検証→次の評価を記録し、文法上の煩雑さと、チートシートの説明不足を分ける。
最低3ラウンド実施し、2回連続で合格、重大な新規誤読なし、最終の保留課題も正解なら終了する。
4ラウンドで到達しなければ、残った問題と未収束を報告して終了する。採点基準を緩めて合格にしない。

小人数のモデル内評価であり、得点は文法の普遍的な優劣や人間の作業時間を表さない。
