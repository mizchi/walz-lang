# Minimal External-Resource Contract

```wat
(type $File (@resource "file" $close))
(@using $file (@resource.new $File (call $open))
  (call $read-file (local.get $file)))
```

`(@inst $resource-handle $File)` is an owned value; `(@inst $borrow $File)` is a borrow allowed only in `@using` or function parameters.
`@resource.close` consumes an owned value and calls its registered destructor once.
`@using` consumes an owned value and closes it on exit through normal values, Result.err, Wasm exceptions, and cancellation.
Return, br, br_if, and `@recur` to an outer loop also close exited using scopes in reverse order. A br_if that does not branch, or a branch that exits only within using, does not close resources early.

Borrows cannot be returned, stored in GC objects, captured by closures, or used as exception payloads.
`@resource.handle` is allowed only as the first argument of a host operation for that kind.
General lifetimes, returning borrowed owned values, and async destructors are not added.
Owned values can be combined with try/catch and throwing calls. Ownership sets at normal, exceptional, and branch destinations are checked, rejecting lost owned values and owned temporaries stranded by later argument evaluation throwing. Uncaught throws cannot leave owned values unconsumed. See [details](core-expressions.md). Borrows also cannot be branch payloads.

Add `resource: {kind, operation}` to the host policy. Operation is new/use/reader/close.
New returns an i32 handle for a synchronous factory value; use converts the first-argument handle to a host value.
Close is synchronous i32→unit. The host implementation receives the original resource object rather than a numeric handle.
Each kind specifies one destructor. Use cannot return owned values. Only the synchronous reader contract can create a Future/Stream independent of the borrow. The host protocol checks single reader acquisition.
Using allows returning these independent Futures/Streams and Tasks that cannot capture borrows. Returning borrows or other owned values is prohibited. See [writers and child tasks](scoped-tasks.md).

The host registry checks task and kind and never reuses closed IDs.
Because Wasm traps cannot be caught, task-exit registry cleanup is also used.
Release proceeds in reverse order and attempts remaining releases if one fails. Cancellation completion waits for release. When a host Promise rejects on abort, guest unwinding and close also wait for disposer completion.
An instance is not reused after destructor failure.

This page's numeric-handle contract is an explicit host adapter for Core+JSPI/SDK Components.
A [native WIT world](native-worlds.md) selected with `--wit` connects imported resources to the Canonical ABI as typed own/borrow values. It uses the types and destructors generated by `walz bind`; numeric resource factories are rejected at native boundaries.
Full WASI resource worlds and network bindings remain subsequent work. SDK numeric imports belong in private library internals.
`examples/resources/` and Node/Chromium checks demonstrate real files and every exit path.
Lean checks the extracted ownership contract. Borrow non-escape, Wasm finally, and the host registry remain in the TCB.
